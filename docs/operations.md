# 本机 CLI 运维说明

[文档索引](README.md) · [完整使用指南](user-guide.md)

本页用于接入后的排错和维护。首次使用请先按完整使用指南操作。

## 日常流程

管理员在 Web UI 修改业务配置，CI 在创建容器前运行 `baoctl sync <APP>`。如果只修改变量，无需重新 init；如果增加机器可读的应用，先 `baoctl app add <APP>`。

`init` 的本机应用可以留空，先完成机器身份初始化。`status` 显示“尚未登记应用”是正常状态；准备好应用 KV 后，再执行 `app add` 和 `sync`。空机器的 `doctor` 只检查连接与机器认证。

所有管理命令都需要 root。普通 SSH + sudo 账号应调用可信部署脚本。部署脚本与二进制应由 root 控制，不允许普通应用修改。

## 凭据与文件生命周期

| 数据 | 保存位置 | 当前生命周期 |
| --- | --- | --- |
| 机器身份、RoleID、SecretID 和应用登记 | `/etc/baoctl/state.json` | 持久保存；SecretID 不自动过期、不限制使用次数 |
| 每次同步的机器 Token | 进程内存 | 默认 5 分钟，最大有效期配置为 10 分钟，用完主动撤销 |
| 应用 env | `/run/baoctl/<APP>.env[.test或.development]` | 主机重启后需重新同步 |
| 原始文件 | `/run/baoctl/<NAME>/<classified>/<FILENAME>` | 主机重启后需重新同步；旧文件名不会自动删除 |

每次 `sync` 使用持久化机器凭据重新登录，取得新的 Token，不依赖上次 Token，也不要求 CI 输入管理员密码。机器凭据被撤销、权限被修改或本地文件损坏时，命令返回失败，不会切换到交互式管理员登录。

长期机器凭据失窃后仍可被反复用于登录，直到被撤销；短期 Token 不能替代凭据泄漏处置。不要打印、复制或将状态文件打入机器模板。备份与退役分别见下文。

## 排错

| 现象 | 检查与处理 |
| --- | --- |
| 连接失败 | DNS、系统时间、系统 CA、HTTPS 443、Server 可用性；不要关闭 TLS 验证 |
| HTTP 503 | Server 可能 sealed；按现有平台流程处理，不让本工具接触 Unseal Keys |
| HTTP 403 | 检查机器凭据是否被撤销，以及该机器的精确应用授权；管理登录也可能因密码错误或锁定失败 |
| HTTP 404 | 确认 `kv/` 是 KV v2，路径为 `<classified>/<typename>/<NAME>/env`，参数默认 `prod/apps`，且应用当前版本未删除 |
| 环境变量格式失败 | 在 Web UI 修正非字符串、多行或无效键；错误信息故意不显示值 |
| 文件解码或摘要失败 | 核对 `B64`、`FILENAME`、`SHA256` 三个字符串字段及原文件是否含末尾换行；不会覆盖已有文件 |
| 目标未登记 | `app add` 和 `sync` 需指定相同 `--classified`、`--typename`，同名的不同分类分别授权 |
| 接入未完成 | 修复上一次错误后运行 `sudo baoctl init`，无需删除状态文件 |
| Policy/AppRole 外部变更 | 在可信管理员会话核对现状，保留证据；工具不强制覆盖，不用删除本地状态绕过 |
| 输出目录不存在 | 主机重启清空 `/run` 是正常现象；发布前 `sync` 会重新创建并生成文件 |
| 文件/目录权限不符 | 先核对所有者和用途，不能对未知目录递归 chmod；默认私有目录 0700、文件 0600 |
| 已有操作正在运行 | 等待当前 CLI 完成；不要删除锁文件，进程结束后内核自动释放锁 |
| Token 撤销失败 | 同步返回失败且不发布新文件；机器 Token 最长 10 分钟。管理员 Token 仍受现有管理员认证 TTL 限制，应在可信管理员会话检查撤销状态 |

`status` 仅报告本地状态；`doctor` 实际检查连接、认证、所有登记目标的读取和数据格式（文件类含 SHA256），不写输出文件。二者不检查容器健康，不会打印变量值。

## 部署失败

同步失败后，保留旧容器运行；不要执行删除、重建步骤。修复 OpenBao 连接或配置后重跑整个幂等发布流程。同步成功但 Docker 发布失败时，由已有 CI/CD 回退镜像与业务版本；必要时先在 Web UI 恢复适合旧应用的配置，再重新同步和发布。

回退 KV 不能自动恢复数据库或外部服务已经撤销的凭据。工具不自动协调数据库密码轮换。

## 凭据泄漏与退役

第一版尚未自动实现身份轮换与退役。处理时需要分别覆盖：机器 SecretID、已经签发的 Token、服务端授权、已渲染 env、容器中的环境变量、已泄漏的业务秘密。只撤销 SecretID 不能收回已签发 Token，只删除本地文件也不能撤销服务端权限。

不要清除其他机器仍使用的业务 KV。高风险服务端操作按平台既有流程取得对象与动作明确的授权。

## 升级与备份

CLI 升级只替换二进制，保留 `/etc/baoctl`；确认没有运行中的命令后进行。当前 schema 为 2，兼容读取 schema 1 的生产应用登记，管理操作保存时升级且保留原机器凭据；不会自动升级未知 schema。旧版二进制不能读取 schema 2。详见 [兼容已有登记](classified-files.md#兼容已有登记)。

`state.json` 含长期机器凭据，不应进入普通配置备份、镜像模板或日志。需要备份时必须按秘密备份的访问与加密要求处理；丢失后应先核对旧身份，再安排重新接入。不要打印该文件排错。

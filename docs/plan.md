# 路线图与验证范围

[文档索引](README.md) · [贡献指南](../CONTRIBUTING.md)

## 已确定的产品约束

- Debian/Ubuntu、Linux amd64、root/sudo 管理。
- 仅本机 CLI，无控制台服务、远程主机管理或常驻 Agent。
- 管理员交互登录接入机器；CI 使用独立机器身份按需同步。
- Web UI 管理 KV；部署前拉取，失败中止，旧容器继续运行。
- 沿用 `kv/prod/apps/<APP>/env` 默认业务路径，扩展 prod/test/dev 与 apps/files，不迁移已有生产数据。

## 本地验收

以代码测试输出为准；以下均为本地验证，不表示生产已接入：

- 格式：特殊字符原值保留；无效类型、控制字符、过大字段拒绝。
- 安全：TLS、拒绝重定向、错误脱敏、文件/目录权限、链接拒绝、锁互斥。
- 失败：403、503、格式错误、配置版本不符、Token 撤销失败不替换旧 env。
- OpenBao 2.7.1：userpass 管理登录、角色/策略创建、wrapping、机器独立认证、授权追加、重复执行与中断恢复。
- 权限：机器不能读无关 APP、写 KV 或写 Policy；撤销 Token 后不能读取。
- Docker：实际 `--env-file` 对空值、空格、美元符号、引号和反斜杠的读取。
- 交互入口：临时容器中以 root 运行完整 CLI，经本地 TLS 代理连接测试 Server，验证隐藏密码输入、init 重跑、app add、非交互 sync/doctor 以及无终端时拒绝管理登录。

## 生产使用前验证

以下步骤由使用者在自己的环境中完成，本地集成测试不替代这些验证。

1. 选择一台机器和一个实际 APP，在可信终端安装并 init。
2. 用机器身份同步并核对字段契约、文件权限与预期配置版本，不展示值。
3. 修改该 APP 的 CI env 路径并串行部署，验证业务健康。
4. 验证 Server 不可用时发布被阻断、旧容器未被停止。
5. 验证主机重启后的首次同步与发布。
6. 再单独决定旧 Agent、旧机器身份及本地副本的退役。

## 后续候选功能

机器凭据轮换、应用撤权/机器退役、受限接入账号、签名发行包与下载安装入口。Compose env-file 和远程编排暂不支持；多行秘密可通过文件类分发。
